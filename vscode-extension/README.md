# Text2Frame Language Support

**RPG ツクール MV/MZ のセリフを、テキストファイルで書くための拡張機能です。**

ツクールのイベント編集画面を1行ずつクリックして開かなくても、ふつうの文書を書くようにセリフを書いて、
ボタンひとつでゲームに入れられます。逆に、ゲームにすでにあるセリフをテキストに取り出すこともできます。

プログラミングの知識は要りません。ターミナル（黒い画面）も使いません。

## この拡張でできること

**やることは、たった2つの往復だけです。**

- **ゲームから取り出す** … ゲームの中のセリフを、テキストファイルに書き出します
- **ゲームに反映** … テキストファイルに書いたセリフを、ゲームに入れます

この2つを行ったり来たりしながら書きます。**どちらも「安全」**で、
あなたがテキストに書いたことも、ツクールの画面で直したことも、勝手には消えません。

書いているあいだは、次のことが自動で助けてくれます。

| | |
| --- | --- |
| 🎨 **色分け** | セリフ・タグ（`<Face: >` など）・コメントが色で見分けられます |
| ✨ **入力補完** | `<` を打つだけでタグの候補が出ます（200 種類以上、説明つき） |
| 📖 **説明の表示** | タグにマウスを合わせると、意味と使用例が出ます |
| 🔍 **書き間違いの指摘** | 閉じ忘れた `<` `>` や空のタグを、その場で知らせます |
| 💾 **保存したら反映** | 「保存時に自動反映」を ON にすると、保存するだけでゲームに入ります |
| 🌐 **多言語対応** | 日本語・英語などを別々のフォルダで持てます（後述） |

## はじめかた（3ステップ）

### 1. ゲームの中身をテキストに取り出す

左端のアクティビティバーにある **Text2Frame のアイコン** をクリックし、
「操作 / Commands」パネルから **「ゲームから取り出す(すべて)」** を選びます。

<!-- TODO(画像): アクティビティバーの Text2Frame アイコンと「操作 / Commands」パネルのスクリーンショット。例 docs/images/panel.png -->

`text/` というフォルダができて、ゲームの中のセリフが一式そろいます。

### 2. テキストを編集する

`text/` の中のファイルを開いて、セリフを書き換えます。ふつうの文書と同じように編集できます。

ただし、次の3つは**触らないでください**。壊れるとゲームに戻せなくなります。

- ファイルのいちばん上、`---` で囲まれた数行（**どのイベントに戻すかのメモ**です）
- `<Face: ...>` のような `< >` で囲まれたタグ
- `<br>` （空行を表す印）

### 3. ゲームに反映する

同じパネルから **「ゲームに反映(すべて)」** を選び、`ja` を選びます。これで反映されます。

> ⚠️ **確認するときは、ツクールのエディタを「保存せずに」開き直してください。**
> 開いたまま保存すると、せっかく反映した内容がツクール側の古い内容で上書きされてしまいます。

## 操作のしかた

コマンドの入口は3つあります。どれを使っても同じです。

- **「操作 / Commands」パネル**（アクティビティバーの Text2Frame アイコン）… すべての操作がグループ別に並んでいます。迷ったらここ
- **コマンドパレット**（`Ctrl+Shift+P` / `Cmd+Shift+P` で開いて `Text2Frame:` と入力）
- **エディタ右上のボタン**（今開いているファイルだけを反映 / 取り出し）

取り出す・反映するときの対象は `text/` フォルダです（設定 `text2frame.textBaseDir` で変えられます）。

| グループ | コマンド | 何をするか |
| --- | --- | --- |
| ゲームに反映 | `ゲームに反映(このファイル)` | 今開いているファイルだけをゲームに入れる |
| ゲームに反映 | `ゲームに反映(すべて)` | テキストのフォルダを丸ごとゲームに入れる |
| ゲームから取り出す | `ゲームから取り出す(このファイル)` | 今のファイルに、ゲーム側の変更だけを取り込む（**あなたの編集は残る**） |
| ゲームから取り出す | `ゲームから取り出す(すべて)` | テキストのフォルダに、ゲーム側の変更だけを取り込む。**初回は一式がそろう** |
| 上級 | `全部取り直す(上書き)` / `コンパイル結果を表示` / `保存時に自動反映 切替` / `会話のみ書き出し` | 補助的な操作 |

### 今どうなっているかは、画面の下に出ます

<!-- TODO(画像): ステータスバーの表示（watching / ok / fail）のスクリーンショット。例 docs/images/statusbar.png -->

| 画面下の表示 | 意味 |
| --- | --- |
| 👁 `T2F: watching` | 保存したら自動で反映する状態 |
| ○ `T2F: off` | 自動反映していない状態（手動で反映します） |
| ✓ `T2F ok` | 直前の反映が成功しました（注意点の数も出ます） |
| ✕ `T2F fail` | 直前の反映が失敗しました（クリックすると理由が見られます） |

## ファイルの先頭にある「宛先」について

取り出したファイルの先頭には、`---` で囲まれた数行が入っています。
これは **「このセリフはゲームのどこに戻すのか」を書いたメモ** です（専門的には front matter と呼びます）。

```text2frame
---
kind: event
mapId: 1
eventId: 1
pageId: 1
---

<Face: Actor1(0)>
こんにちは
```

- `kind: event` … マップの上に置いたイベント
- `mapId` / `eventId` / `pageId` … そのイベントの場所（マップ番号・イベント番号・ページ番号）

コモンイベントの場合はこうなります。

```text2frame
---
kind: common
commonEventId: 3
---

セリフ…
```

**この部分を書き換えると、別のイベントに書き込まれてしまいます。** ふだんは触らないでください。
自分で新しいファイルを作るときだけ、戻したいイベントに合わせて書きます。

## 「反映」で、ツクール側の編集が消えないしくみ

「ゲームに反映」は既定で**安全**です。テキストに書いたことと、ツクールの画面で加えた編集の
両方をできるだけ両立させ、勝手に消しません。

- テキストにしかないセリフは、ゲームに入ります。
- ツクールの画面でしか作れないもの（移動・分岐・スイッチ操作など）は、そのまま残ります。
- **同じ場所を両方で別々に**変更していたときだけ、**両方を残して**あなたに選んでもらいます（下記）。

「テキストの内容で全部やり直したい」ときだけ、設定を **全部上書き** に変えてください
（ツクール側の編集は消えます）。

### 両方で変更していたとき（競合）

同じ場所を両方で変えていると、その部分は**両方残り**、次のような目印で囲まれます。

```
=== テキストの変更 / from text ===
（テキスト側の内容）
=== ゲームの変更 / from game ===
（ゲーム側の内容）
=== どちらかを残し、この目印3行を消す / keep one, delete these 3 marker lines ===
```

<!-- TODO(画像): 競合表示の実例スクリーンショット（目印コメントで両方残っている様子）。例 docs/images/conflict.png -->

**直し方は2手です。**

1. 残したい方だけにして、**目印の3行を消す**
2. もう一度「ゲームに反映」する

これで、あなたが選んだ内容がゲーム側にも入ります。設定を変える必要はありません。
目印を消さないまま反映すると、そのファイルは対象から外れます（目印ごと二重に増えてしまうため）。

この目印をテキスト側に書き戻すかどうかは、設定 `text2frame.writeBackAfterMerge` で変えられます
（既定＝競合したときだけ書き戻す）。

### そのほかの安全策

- **ゲームのデータが外で書き換わっていたら、警告します。** 反映先のファイルが、この拡張が最後に書き込んだ後に
  ツクールなどで更新されていて、かつ設定が **全部上書き** のときだけ、上書き前に確認が出ます
  （既定の「安全に反映」はツクール側の編集を残すので、確認は出ません）。
  - **[安全に反映する(おすすめ)]** … その回だけ安全に反映し、ツクール側の編集を残す
  - **[全部上書きする]** … テキストで上書きする（直前のデータは `*.json.conflict.bak` に退避されます）
  - **[ゲームの内容を取り込む]** … 反映せず、最新の内容をテキストへ取り出す
  - **[キャンセル]** … 何もしない
- **いちばん最初の書き込み前に、元のデータを `*.bak` として1度だけ取っておきます。**
- **書き方が間違っているときは、書き込まずに止まります。** 壊れたデータが入ることはありません。
- 反映時の注意点は、通知と「Text2Frame Deploy」という出力欄に出ます。
  - 中身が変わっただけなら「`Block changed / ブロックが変更されます`」、
    テキストから消えて**本当に削除される**ものだけ「`Block removed / ブロックが削除されます`」と出ます。

## 英語版（多言語版）を作る

この拡張に「翻訳機能」はありません。あるのは **テキストのフォルダをゲームと行き来させるしくみ**だけです。
言語ごとにフォルダを分け、設定 `text2frame.textBaseDir` で切り替えて使います。
次の3ステップで英語版が作れます。

1. **ゲームから取り出す** — 設定 `text2frame.textBaseDir` を `text-en` にしてから、
   「操作」パネル →「ゲームから取り出す(すべて)」。
   - `text-en/` にゲームの内容が入ります。これが翻訳の出発点です。
   - これは**安全な取り込み**なので、後でもう一度実行しても**訳した文は消えません**（ゲーム側で増えたセリフだけ入ってきます）。
2. **翻訳する** — `text-en/` のセリフと選択肢を英語にします。
   - 先頭の `---` の部分、`<Face: ...>` などのタグ、`<br>` は触らないでください。
3. **ゲームに反映** — 「ゲームに反映(すべて)」を実行します。
   - 既定は安全な反映なので、ツクール側で加えた編集（移動・分岐・スイッチ等）を保ったまま訳文が入ります。
   - 日本語版に戻すときは `text2frame.textBaseDir` を `text` に戻してください。

> 白紙からやり直したいときだけ、上級の「**全部取り直す(上書き)**」を使ってください（訳文は失われます）。

> 1ファイルずつ編集しながら確認したい場合は、「保存時に自動反映」を ON にすると、
> 保存するたびに先頭の宛先に従って自動で反映されます。

## 書き方の例

`.t2f` または `.text2frame` という拡張子のファイルを作って編集します
（Text2Frame の宛先メモが入った `.txt` も自動で認識されます）。

```text2frame
<comment>
* オープニングシーン
</comment>

今日も一日がんばるぞい！

<Face: Actor1(0)>
今日も一日がんばるぞい！（顔付き）

<WindowPosition: Bottom>
<Background: Dim>
<Name: 涼風青葉>
今日も一日がんばるぞい！

% コメント行
<PlayBGM: Theme1>

<ShowChoices: Window, Right, 1, 2>
<When: はい>
そうですか！
<When: いいえ>
残念です。
<End>

<wait: 60>
```

- **空行**が、メッセージウィンドウの区切りです。空行で区切ると次のウィンドウになります。
- 行の頭に `%` を書くと、その行はゲームに入りません（メモとして使えます）。
- 同じウィンドウの中で空行を入れたいときは `<br>` と書きます。

## よく使うタグ

**見た目の設定**

| タグ | 何が変わるか |
| --- | --- |
| `<Face: >` | 顔グラフィック |
| `<WindowPosition: >` | ウィンドウの位置（Top / Middle / Bottom） |
| `<Background: >` | 背景（Window / Dim / Transparent） |
| `<Name: >` | 話し手の名前（MZ のみ） |

顔・背景・位置は、**いつもと同じ値なら書かなくて構いません**。書かなければ、反映のときに
既定値がそのまま使われます。取り出したテキストでも、3つとも既定ならタグの行ごと消えて、セリフだけが並びます。

```text2frame
こんにちは            ← 顔なし・ウィンドウ背景・下に表示（＝既定のまま）

<Face: Actor1(2)>     ← 顔だけ変えたいので、顔だけ書く
やあ！
```

ゲームの見た目は変わりません（省いた所は反映時に既定値が補われます）。
全部書き出したいときは、設定 `text2frame.omitDefaultTags` を OFF にしてください。

**イベントコマンド**

| タグ | 何ができるか |
| --- | --- |
| `<ShowChoices: >` / `<When: >` / `<End>` | 選択肢と分岐 |
| `<Switch: >` / `<Set: >` / `<If: >` | スイッチ・変数・条件分岐 |
| `<PlayBGM: >` / `<PlaySE: >` | BGM・効果音 |
| `<wait: >` | ウェイト（待ち時間） |
| `<script>…</script>` | JavaScript の実行 |

…ほか 100 以上のツクールのイベントコマンドに対応しています。
全部を覚える必要はありません。`<` を打てば候補が出ます。

## 設定

VS Code の設定画面（`Ctrl+,` / `Cmd+,`）で `text2frame` と検索すると出てきます。
**ふだんは全部そのままで大丈夫です。**

| 設定 | 既定値 | 何を決めるか |
| --- | --- | --- |
| `text2frame.strategy` | 安全に反映 | ゲームへの入れ方。**安全に反映**（ツクール側の編集を消さない・既定）/ **全部上書き** |
| `text2frame.writeBackAfterMerge` | 競合したときだけ | 競合したとき、目印をテキストに書き戻して直せるようにするか。しない / 競合時だけ / 反映のたび |
| `text2frame.englishTag` | ON | 取り出すときのタグを英語（`<Face: >`）にするか、日本語（`<顔: >`）にするか |
| `text2frame.omitDefaultTags` | ON | 取り出すとき、既定と同じ顔・背景・位置のタグを書かないか（下記） |
| `text2frame.dataDir` | `data` | ゲームのデータフォルダの場所 |
| `text2frame.textBaseDir` | `text` | テキストを置くフォルダの場所 |
| `text2frame.modulePath` | （空） | `Text2Frame.js` の場所を自分で指定したいとき（ふつうは空のままで自動で見つかります） |

## 動かすのに必要なもの

**VS Code 1.85.0 以上だけです。** Node.js を別に入れる必要はありません。

この拡張は VS Code に内蔵された仕組みの上で動くので、**Windows でもそのまま動きます**。

## 困ったとき

| 症状 | 原因と対処 |
| --- | --- |
| 反映したのにゲームに出ない | ツクールのエディタを**保存せずに**開き直してください。開いたまま保存すると古い内容で上書きされます |
| 反映が `T2F fail` になる | 書き方の間違いです。画面下の `T2F fail` をクリックすると理由が出ます。`< >` の閉じ忘れが多いです |
| 目印の3行がテキストに入っている | 同じ場所を両方で変えた印です。残す方だけにして3行を消し、もう一度反映してください |
| 取り出したら翻訳が消えた | 「全部取り直す(上書き)」を使うと消えます。ふだんは「ゲームから取り出す」を使ってください |
| `.txt` に色がつかない | 先頭に `---` で囲まれた宛先メモがあるファイルだけが対象です。無い `.txt` はふつうのテキストとして扱われます |

## 開発者向け

```bash
npm install        # 依存をインストール
npm run compile    # TypeScript をビルド（out/）
npm run watch      # 変更を監視してビルド
npm run lint       # ESLint
```

`F5` で Extension Development Host を起動するとデバッグできます。

パッケージ（`.vsix`）化の前に、同梱コンパイラを生成します（`vscode:prepublish` で自動実行）。

```bash
npm run bundle-compiler   # 親リポジトリの Text2Frame.js を lib/ にコピー
```

ターミナルから同じことをしたい場合は、本体リポジトリの CLI（`npx t2f-sync --watch` など）もあります。

## 情報

- **対象拡張子**: `.t2f`, `.text2frame`
- **`.txt` の自動認識**: 先頭に Text2Frame の宛先メモ（`---\nkind: ...`）を持つ `.txt` を開くと、自動的に text2frame として扱われ、色分け・補完・説明・指摘が有効になります（リネーム不要）。宛先メモの無いふつうの `.txt` は対象外です
- **必要環境**: VS Code 1.85.0 以上
- **ライセンス**: MIT
