# Text2Frame Language Support

**RPG ツクール MV/MZ のイベントを、テキストで書いて、見て、試せる拡張機能です。**

ツクールのイベント編集画面で1行ずつ入力する代わりに、ふつうの文書を書くようにセリフやイベントを書けます。
書いたものは、ツクールと同じ見た目で確かめられます。ボタンひとつでゲームに入れて、そのまま VS Code の中で遊んで試せます。

プログラミングの知識は要りません。ターミナル（黒い画面）も使いません。

## この拡張でできること

できることは、大きく分けて5つです。どれから使ってもかまいません。

| | できること | くわしくは |
| --- | --- | --- |
| ✏️ **書く** | 色分け、`<` を打つと出るタグの候補、タグの説明、書き間違いの指摘。スイッチや変数の番号の横には、データベースの名前が薄く出ます | [テキストを書く](#テキストを書く) |
| 👀 **見る** | 書いたテキストを、ツクールのイベント編集画面と同じ形で横に並べます。顔画像も出て、BGM・効果音はその場で鳴らせます | [プレビューで見る](#プレビューで見る) |
| 🔄 **ゲームとやりとりする** | ゲームのセリフをテキストに取り出し、書いたテキストをゲームに入れます。ツクールの画面で直したところは勝手に消えません。あとから前の状態にも戻せます | [ゲームとやりとりする](#ゲームとやりとりする取り出す反映) |
| 🔍 **調べる** | マップ・イベント・コモンイベントの一覧と、スイッチ・変数などのデータベースの一覧が出ます。そのスイッチを使っている箇所もすぐ探せます | [プロジェクトを見渡す](#プロジェクトを見渡す) |
| ▶️ **試す** | VS Code の中でゲームをテストプレイできます。遊びながら、スイッチ・変数・アイテムなどの今の値を見たり、書き換えたりできます。決めた行でゲームを止めて、1行ずつ進めることもできます | [テストプレイとデバッグ](#テストプレイとデバッグ) |

## 画面の見取り図

この拡張の入口は、次の4か所です。

| 場所 | 何があるか |
| --- | --- |
| **左端の Text2Frame のアイコン**（本のマーク） | 5つの欄が出ます。<br>・「操作」… できることがボタンで並んでいます。**迷ったらここ**。中は6つに分かれていて、最初は「よく使う」「試す・デバッグ」だけ開いています（ほかは見出しを押すと開きます）<br>・「Maps / Common Events」… マップ・イベント・コモンイベントの一覧<br>・「マップのつながり」… 場所移動でどのマップへ行けるか（いつもは閉じています）<br>・「履歴」… 反映・取り出しの前の中身。前の状態に戻せます（いつもは閉じています）<br>・「データベース」… スイッチ・変数・アイテムなどの一覧 |
| **エディタの右上のボタン** | テキストを開いているときに出ます。「ゲームに反映(このファイル)」「ゲームから取り出す(このファイル)」「プレビューを開く」 |
| **画面のいちばん下** | 左下の `T2F` の表示で、ゲームへの反映がうまくいったかが分かります。下のパネル「Text2Frame デバッグプレイ」には、テストプレイ中の値が出ます |
| **エディタのタブ** | プレビュー、テストプレイのゲーム画面、デバッグメニューは、ふつうのファイルと同じくタブで開きます。好きな場所へドラッグして動かせます |

ほかに、**コマンドパレット**（`Ctrl+Shift+P` / `Cmd+Shift+P` で開いて `Text2Frame` と入力）からも、ほとんどの操作を呼び出せます。

## はじめかた

### 1. 拡張を入れる

VS Code の左端にある拡張機能のアイコン（`Ctrl+Shift+X` / `Cmd+Shift+X`）を押し、
検索欄に **Text2Frame** と入力して、「インストール」を押します。

### 2. ゲームのフォルダを開く

VS Code のメニュー「ファイル」→「フォルダーを開く」で、**ツクールのゲームのフォルダ**を開きます。
`data` という名前のフォルダが中にある、いちばん上のフォルダです（`index.html` や、ツクールのプロジェクトファイルがある所）。

### 3. ゲームのセリフをテキストに取り出す

左端の Text2Frame のアイコン →「操作」→「まとめて反映・取り出す」→ **「すべてゲームから取り出す」** を押します。
`text` というフォルダができて、ゲームの中のセリフが一式そろいます。

### 4. テキストを直す

`text` の中のファイルを開いて、セリフを書き換えます。ふつうの文書と同じように編集できます。

ただし、次の3つは**触らないでください**。書き換えると、ゲームに正しく戻せなくなります。

- ファイルのいちばん上の、`---` で囲まれた数行（**どのイベントに戻すかのメモ**です）
- `<Face: ...>` のような、`< >` で囲まれたタグ
- `<br>`（空行を表す印）

### 5. プレビューで見る

エディタの右上の「プレビューを開く」を押すと、ツクールのイベント編集画面と同じ形で表示されます。

### 6. ゲームに反映する

「操作」→「まとめて反映・取り出す」→ **「すべてゲームに反映」** を押します。これでゲームのデータに入ります。

### 7. テストプレイで確かめる

「操作」→「試す・デバッグ」→ **「テストプレイ」** を押すと、VS Code の中でゲームが始まります。

> ⚠️ **ツクールのエディタで確かめるときは、ツクールを「保存せずに」開き直してください。**
> ツクールを開いたまま保存すると、反映した内容がツクール側の古い内容で上書きされてしまいます。

## テキストを書く

ゲームから取り出したファイル（`.txt`）を、そのまま書き換えられます。
自分で新しく作るときは、`.t2f` または `.text2frame` という拡張子で作ります。

### 書き方の例

```text2frame
<comment>
* オープニングシーン
</comment>

今日も一日がんばるぞい！

<Face: Actor1(0)>
<Name: 涼風青葉>
顔と名前つきのセリフです。

% この行はメモです。ゲームには入りません
<PlayBGM: Theme1>

<ShowChoices: Window, Right, 1, 2>
<When: はい>
そうですか！
<When: いいえ>
残念です。
<End>

<Wait: 60>
```

- **空行**で、メッセージウィンドウが次に切り替わります。
- 行の頭に `%` を書くと、その行はゲームに入りません。メモに使えます。
- 同じウィンドウの中で空行を入れたいときは、`<br>` と書きます。

### 書くのを助けてくれる機能

| 機能 | どう働くか |
| --- | --- |
| 色分け | セリフ・タグ・コメントが色で見分けられます |
| タグの候補 | `<` を打つと、タグの候補が説明つきで出ます。200種類以上あるので、覚える必要はありません |
| タグの説明 | タグにマウスを合わせると、意味と使用例が出ます |
| 書き間違いの指摘 | `<` `>` の閉じ忘れや空のタグに、波線が付きます |
| データベースの名前 | `<Switch: 12, ON>` の `12` の横に、スイッチ12の名前が薄く出ます。ファイルには書き込まれません。マウスを合わせると、同じ名前の番号や顔画像も出ます。データベースに無い番号には印が付きます |
| 名前から番号を入れる | 番号を書く所で候補を出すと、名前から探して番号を入れられます |
| 色見本 | 画面の色調変更・フラッシュなど、色を指定するタグの横に小さな色見本が出ます |
| メッセージのはみ出し | 文章がメッセージウィンドウの幅を超える行に波線が付きます。顔グラフィックがあるときは、そのぶん狭く数えます。プレビューにも ⚠ が出ます |

メッセージのはみ出しは、全角1文字・半角0.5文字として、`System.json` の画面の幅と文字の大きさから数えます（`\C[n]` などの制御文字は見た目の幅に直します）。フォントやプラグインによっては、目安になります。
自動で改行するプラグイン（名前に WordWrap・AutoLineBreak などを含むもの）が有効なプロジェクトでは、はみ出しは調べません。設定 `text2frame.messageCheck` で、いつも調べる・調べないを選べます。

### 顔画像・音を見て選ぶ

入れたい行にカーソルを置いて、右クリック →「顔画像を選ぶ」または「音を選ぶ」を押すと、「素材を選ぶ」のタブが開きます。

- **顔画像**: 顔画像のファイルごとに、8つの顔が並びます。押すと、カーソルの行に `<Face: 名前(番号)>` が入ります。行にもう顔のタグがあれば、中身だけ置き換えます。
- **音**: BGM・BGS・ME・SE のタブに、音声のファイルが並びます。▶ で試し聞きでき（もう一度押すと止まります）、「入れる」を押すと `<PlayBGM: 名前, 90, 100, 0>` などが入ります。行に同じ種類のタグがあれば、名前だけ置き換えます。
- `<Face:` の候補のいちばん上の「一覧から見て選ぶ…」や、顔・音のタグの行の電球からも開けます。

### 電球（クイックフィックス）で直す

波線の所にカーソルを置くと出る電球のマーク（または `Ctrl+.` / `Cmd+.`）から、直し方を選べます。

| 波線が付くもの | 選べる直し方 |
| --- | --- |
| タグの名前の打ち間違い（例: `<Fase:`）。タグとして読まれず、ゲームにそのまま文字で出てしまう行です | 「`<Face` に直す」など、近いタグの名前 |
| タグの閉じ忘れ | 行の終わりに `>` を足す |
| 空のタグ `<>` | 消す |
| データベースに無い番号・名前の無い番号 | 候補から選び直す |
| 競合の目印 | テキストの方を残す / ゲームの方を残す / 両方残して目印だけ消す |

### スニペット（よく使う書き方の型）

- **行の頭で `/` を打つ**と、選択肢・条件分岐・顔付きのセリフ・場所移動・BGM などの型が候補に出ます。`/選択肢2` のように続けて打つと絞り込めます。
  - 選ぶと、書き換える所にカーソルが入ります。`Tab` で次の書き換える所へ移ります。
  - 文章の途中で打った `/` や、ふつうに文章を打っているときには出ません。
- 「操作」→「書くのを助ける」→「スニペットを入れる」からも、一覧で選べます。
- **自分で作る**: よく使う部分をエディタで選び、右クリック →「選んだ部分をスニペットにする」。呼び出す言葉を入れると、行の頭で `/言葉` と打つと出るようになります。
  - ゲームのフォルダの `.vscode/text2frame-snippets.json` に保存されるので、同じフォルダを使う人とも共有できます。
  - 作ったスニペットを直すときは「操作」→「書くのを助ける」→「スニペットを編集する」を使います。

### テキストの中を行き来する

| 操作 | できること |
| --- | --- |
| **定義へ移動**（`F12`、または `Ctrl`（Mac は `Cmd`）を押しながらクリック） | 次の所へ飛びます。<br>・`<CommonEvent: 7>` → コモンイベント7のテキスト<br>・`<JumpToLabel: 最後>` → 同じテキストの `<Label: 最後>`<br>・スイッチ・変数・セルフスイッチの番号 → その値を書き換えている所<br>・場所移動のマップ番号 → そのマップのイベントのテキスト |
| **参照の一覧**（`Shift+F12`） | そのスイッチ・変数・コモンイベントなどを使っている所を、プロジェクト全体から一覧にします |
| **名前で開く**（`Ctrl+T` / `Cmd+T`） | マップ名・イベント名・コモンイベント名の一部を打つと、そのテキストを開けます |
| **アウトライン** | 左の「エクスプローラー」の下の「アウトライン」に、選択肢・条件分岐・ラベル・メッセージ（話し手つき）が入れ子で並びます。押すとその行へ飛びます |
| **折りたたみ** | 選択肢・条件分岐・ループ・注釈などを、行番号の横の `˅` で畳めます |
| **スティッキースクロール** | 長いイベントをスクロールしても、今いる選択肢や条件分岐の行が画面の上に残ります |
| **つながりを見る**（`Shift+Alt+H`） | 下の「イベントのつながりをたどる」を見てください |

### イベントのつながりをたどる

「このイベントが何をして、その先で何が起きるか」を、VS Code の**呼び出し階層**でたどれます。

- 開き方は3つあります。
  - テキストの上で右クリック →「呼び出し階層を表示」（`Shift+Alt+H`）
  - 「操作」→「調べる」→「イベントのつながりを見る」
  - 「Maps / Common Events」一覧の行を右クリック →「つながりを見る」
- **ここから**（出ていく方）には、次が並びます。
  - 呼ぶコモンイベント
  - 場所移動の行き先のマップ
  - ON / OFF にするスイッチ・セルフスイッチ、変える変数
- **ここへ**（入ってくる方）には、次が並びます。ボタンで向きを切り替えます。
  - このコモンイベントを呼んでいるページ
  - このマップへ移動させているページ
  - このスイッチを変えているページ
- スイッチの行をさらに開くと、**そのスイッチが ON になると出てくるページ**や、動き出すコモンイベントが並びます。こうして「スイッチを ON にする → 別のイベントが出てくる」と、何段でもたどれます。
- 行を押すと、その所へ飛びます。テキストがまだ無いページは、ゲームのデータから作った**読むだけの画面**で開きます。
- つながりは、ゲームに反映済みの内容から調べます。**開いているテキストは、保存前の書きかけも入ります。**

### よく使うタグ

| タグ | 何ができるか |
| --- | --- |
| `<Face: >` | 顔グラフィック |
| `<Name: >` | 話し手の名前（MZ のみ） |
| `<WindowPosition: >` / `<Background: >` | ウィンドウの位置（上・中・下）/ 背景（ウィンドウ・暗くする・透明） |
| `<ShowChoices: >` / `<When: >` / `<End>` | 選択肢と分岐 |
| `<Switch: >` / `<Set: >` / `<If: >` | スイッチ・変数・条件分岐 |
| `<PlayBGM: >` / `<PlaySE: >` | BGM・効果音 |
| `<Wait: >` | ウェイト（待ち時間） |

ほかにも100以上のイベントコマンドに対応しています。

顔・背景・位置が**いつもと同じなら、タグを書かなくてかまいません**。
書かなかったところは、反映のときに既定の値が入ります。取り出したテキストでも、既定のままのタグは省かれます
（全部書き出したいときは、設定 `text2frame.omitDefaultTags` を OFF にします）。

## プレビューで見る

書いたテキストを、ツクールのイベント編集画面と同じ形で並べて見せます。
番号にはデータベースの名前が添えられ、「文章の表示」には顔画像が出ます。

**開き方**: テキストを開いて、エディタの右上の「プレビューを開く」を押します。

- 開いているテキストに付いていきます。別のテキストに切り替えると、プレビューも切り替わります。
- 書き換えると、少し間を置いて描き直されます。書き間違いがある間は、最後に正しかった形のまま、上にエラーが出ます。
- エディタのカーソルがある行が、プレビューでも強調され、見えていなければそこまでスクロールします。顔グラフィックがある行でも、その下の文章（4行ぶん）まで見えるように寄せます。
- **プレビューの行を押すと、テキストのその行へ飛びます。**
- BGM・BGS・ME・効果音の行には ▶ が付きます。押すとその場で鳴り、もう一度押すと止まります。
- ふだんはテキストの右に開きます。テストプレイ中は、右にゲームを置くので、テキストの下に開きます。

## ゲームとやりとりする（取り出す・反映）

**やることは2つの往復です。**

- **ゲームから取り出す** … ゲームの中のセリフを、テキストに書き出します
- **ゲームに反映** … テキストに書いたものを、ゲームに入れます

どちらも「このファイル」だけか「すべて」かを選べます。

| やりたいこと | 押す場所 |
| --- | --- |
| 今のファイルだけ | エディタの右上のボタン、または「操作」→「よく使う」の「ゲームに反映(このファイル)」「ゲームから取り出す(このファイル)」 |
| テキストのフォルダ全部 | 「操作」→「まとめて反映・取り出す」の「すべてゲームに反映」「すべてゲームから取り出す」 |
| 一覧の中のあるページだけ | 「Maps / Common Events」の行にマウスを合わせると出るボタン |

「すべて」は、テキストが多いと少し時間がかかります（2900ファイルで10〜15秒ほど）。進み具合が右下に出て、その間も編集を続けられます。
途中で「キャンセル」を押すと、そこで止まります。済んだ分はそのまま残り、[履歴](#前の状態に戻す履歴)からまとめて戻せます。

### どちらも「安全」です

- **取り出す**ときは、ゲーム側で変わったところだけがテキストに入ります。**あなたが書いたところは残ります。**
- **反映**するときは、ツクールの画面でしか作れないもの（移動ルート・分岐・スイッチ操作など）を、そのまま残します。
- 同じ場所をテキストとツクールの両方で別々に変えていたときだけ、**両方を残して**あなたに選んでもらいます。

「テキストの内容で全部やり直したい」ときだけ、設定 `text2frame.strategy` を「テキストで全部上書き」に変えてください（ツクール側の編集は消えます）。
なお、書き方が間違っているときは、ゲームに書き込まずに止まります。壊れたデータが入ることはありません。

### 書き込む前に、変わる所を確かめる

ボタンで反映・取り出しをすると、すぐには書き込まず、まず**変わる所が差分の画面で開きます**。

- 反映のときは、左が「ゲームの今」、右が「反映後」です。取り出しのときは、左が「今のテキスト」、右が「取り出し後」です。
- 消える行は赤、増える行は緑で、行番号も付きます。左右に並べる表示と、1列に並べる表示を切り替えられます（差分の画面の右上の「…」から）。
- 「すべて」のときは、変わるファイルが1つの画面にまとめて並びます。
- 画面の右上の「✓」か、通知の「反映する」（取り出しは「書き込む」）を押すと、書き込みます。
- 「やめる」を押すか、差分のタブを閉じると、何も書き込みません。
- 何も変わらないときは、確かめずにそのまま進みます。
- 確かめているあいだにテキストやゲームが変わったときは、書き込まずに、もう一度確かめ直します。

保存時の自動反映は、確かめずに書き込みます。
いつも確かめずにすぐ書き込みたいときは、設定 `text2frame.reviewBeforeApply` を OFF にします。

### 両方で変えていたとき（競合）

テキストのその部分に両方の版が残り、次のような目印で囲まれます。ゲームには目印を入れず、ゲームの版のままにします。

```
=== テキストの変更 / from text ===
（テキスト側の内容）
=== ゲームの変更 / from game ===
（ゲーム側の内容）
=== どちらかを残し、この目印3行を消す / keep one, delete these 3 marker lines ===
```

**直し方は2手です。**

1. 残したい方だけにして、**目印の3行を消す**
2. もう一度「ゲームに反映」する

目印を消さないまま反映すると、そのファイルは反映されません。

### ファイルの先頭の「宛先のメモ」

取り出したファイルの先頭には、`---` で囲まれた数行があります。**このセリフをゲームのどこに戻すか**のメモです。

```text2frame
---
kind: event
mapId: 1
eventId: 1
pageId: 1
---

こんにちは
```

- `kind: event` はマップの上のイベント、`kind: common` はコモンイベント（`commonEventId: 3` のように書きます）です。
- `mapId` / `eventId` / `pageId` は、マップ番号・イベント番号・ページ番号です。

**書き換えると、別のイベントに書き込まれてしまいます。** 自分で新しいファイルを作るときだけ、戻したいイベントに合わせて書きます。

### 保存するだけで反映する

「操作」→「まとめて反映・取り出す」→「保存時に自動反映 切替」を ON にすると、ファイルを保存するたびに、そのファイルがゲームに入ります。

### 前の状態に戻す（履歴）

反映や取り出しでファイルを書き換える**直前の中身**を、自動で控えておきます。あとから「やっぱり前のほうがよかった」と思ったら、いつでもその操作の前に戻せます。git などの準備は要りません。

- 左の Text2Frame のアイコン →「**履歴**」欄（または「操作」→「上級」→「履歴(前の状態に戻す)」）に、操作が新しい順に並びます。
  - 例: 「ゲームに反映 text/map003_event005_page2.txt　11:52・3分前・1ファイル」
  - 開くと、その操作で書き換わったファイルが並びます。**押すと差分**（控え ↔ 今）が出ます。ゲームのデータは、そのページの中身をテキストに直して比べます。
- **戻す**: 操作の行を右クリック →「**この操作の前に戻す**」。ファイルの行からは「このファイルだけ戻す」もできます。
  - 戻したことも履歴に残るので、「戻したのを取り消す」もできます。
  - その操作で**新しくできたファイル**（初めて取り出したテキストなど）は、戻しても消しません。知らせに名前が出るので、要らなければ自分で消してください。
  - 保存していない変更があるテキストは戻しません。先に保存するか、元に戻してください。
  - テストプレイ中にゲームのデータを戻したら、ゲームを読み直してください。
- 保存時の自動反映は、同じテキストで5分以内に続いた分を1つにまとめます（保存のたびに並ばないように）。
- 控えは、ゲームのフォルダの `.t2f-history` に置きます。
  - 残すのは最新の100回ぶんです（設定 `text2frame.history.keep`）。合計が300MBを超えたときも、古いものから消えます。
  - このフォルダは消してもゲームの動きには関係しません。ツクールのデプロイメントの前などに、消してもかまいません。
  - git で管理しているフォルダでも、控えは git に入りません（フォルダの中に、自分専用の `.gitignore` を置いています）。

### 画面の左下の表示

| 表示 | 意味 |
| --- | --- |
| 👁 `T2F: watching` | 保存したら自動で反映する状態 |
| ○ `T2F: off` | 自動では反映しない状態（ボタンで反映します） |
| ✓ `T2F ok` | 直前の反映がうまくいきました |
| ✕ `T2F fail` | 直前の反映がうまくいきませんでした。押すと理由が出ます |

## プロジェクトを見渡す

左端の Text2Frame のアイコンの中に、3つの一覧があります。

### 「Maps / Common Events」一覧

ゲームのマップ → イベント → ページ、コモンイベントが、ツリーで並びます。マップの親子と並び順・名前は、ツクールのエディタのマップツリーと同じです。

- **イベントの行**には、名前と `EV005 (8,11)` の番号・座標が出ます。
- **ページの行**には、トリガーと出現条件が出ます（例: `自動実行・S0012 が ON・セルフ A が ON`）。マウスを合わせると、スイッチの名前つきで出ます。
- ページやコモンイベントを押すと、そのテキストが開きます。まだテキストが無ければ、取り出すかを聞かれます。
  - テキストのある行と、まだ無い行は、アイコンで見分けられます。
  - 保存したテキストがゲームに反映されていない行には、**未反映**と出ます。
- 行にマウスを合わせると出るボタンで、そのページだけを取り出したり、反映したりできます。
- テキストを開くと、その行が一覧の中で選ばれます。
- 一覧を選んで文字を打つと、名前で絞り込めます。
- 行を右クリックすると、「イベントの前に立つ」「このページをすぐ実行」でテストプレイから試せます（[このイベントから試す](#このイベントから試す)）。

**テストプレイ中は**、一覧のいちばん上に「今いるマップ」が出ます。

- そのマップのイベントが並び、今出ているページ・並列処理で動いているもの・実行中のものに印が付きます。
- どのページも出ていないイベントは「出ていない」と出ます。出現条件がそろっていない、ということです。
- 今いるマップは、下のツリーの中でも「● いまここ」と出ます。

### 「マップのつながり」一覧

場所移動（`<TransferPlayer: …>`）で、**どのマップからどのマップへ行けるか**が並びます。いつもは閉じているので、見出しを押して開いてください。

- 見るマップは、**今開いているテキストのマップ**です。「Maps / Common Events」一覧の行を右クリック →「マップのつながりを見る」でも選べます。
- **テストプレイ中は、ゲームが今いるマップに付いていきます。** マップを移動するたびに切り替わり、見出しに「● いまここ」と出ます。
  - 自分で別のテキストを開けば、そちらに切り替わります。ゲームが次のマップへ移るまでは、そのままです。
- 「行き先のマップ」「ここへ来るマップ」の2つに分かれます。
- マップの下には、移動しているイベントとページが出ます。押すと、その移動の行へ飛びます。
- マップの行を開くと、その先のマップが出ます。何段でもたどれます。すでに出てきたマップは「(上と同じ)」と出て、そこで止まります。
- 行き先を変数で決めている移動は、「変数で決まる行き先」としてまとめて出ます。

**図でも見られます。**「操作」→「調べる」→「マップのつながりを図で見る」か、一覧の行の右クリックで、丸と矢印の図がタブで開きます。

- 真ん中が今のマップで、右へ行くほど遠い（移動の回数が多い）マップです。
- 矢印は移動の向きです。行き来できる所は両向き、乗り物は点線になります。
- **丸を押すと**、そのマップが真ん中になって描き直します。**矢印を押すと**、移動している行へ飛びます。
- 上の欄で、何段先まで出すか・乗り物も出すかを選べます。「全部のマップを出す」もできます（多いときは先に確かめます）。

### 「データベース」一覧

スイッチ・変数・マップ・アイテムなどが、番号と名前で並びます。見るだけで、書き換えはしません。

- **スイッチや変数を押すと**、それを使っている箇所が、前後の行つきで一覧になります。一覧の行を押すと、そのテキストへ飛びます。
- スイッチや変数以外を押すと、開いているテキストのカーソルの位置に、その番号が入ります。
- 虫眼鏡のボタンで、「スイッチ12として」使っている箇所を探せます（ただの数字の 12 は拾いません）。
- 右クリックからも、「番号を挿入」「使っている箇所を探す」などを選べます。
- テストプレイ中は、スイッチと変数の今の値も一緒に出ます。

### プロジェクト全体を検査する

「操作」→「調べる」→「プロジェクト全体を検査」を押すと、全部のテキストを調べて、見つかった問題を VS Code の「問題」パネルに一覧で出します。押すと、その行へ飛べます。

- 書き間違い（閉じ忘れ・空のタグ・タグとして読まれない行・コンパイルできない所）
- データベースに無い番号、無い顔画像、無い音声ファイル
- 未解決の競合の目印
- メッセージのはみ出し
- 先頭の宛先のメモが指すマップ・イベント・ページが、ゲームに無いもの
- ゲームに反映されていない変更があるテキスト

テキストを書き換えると、そのファイルの検査の結果は消えて、ふだんの指摘に切り替わります。直したあとで、もう一度検査してください。

テキストが多いプロジェクトでは、少し時間がかかります（2900ファイルで10秒ほど）。進み具合が右下に出て、押せば途中で止められます。検査の間も、ふつうに編集を続けられます。

## テストプレイとデバッグ

VS Code の中でゲームを動かして、試せます。ツクールのテストプレイと同じテストモードなので、`F9` のデバッグ画面も使えます。

### 始める・止める

- **始める**: 「操作」→「試す・デバッグ」→「テストプレイ」。テキストの右にゲームのタブが開きます。
  - 2回目からは、同じゲームのタブを使い回して読み直します。タブを好きな場所へ動かしておけば、次もそこに出ます。
  - いつものブラウザで遊びたいときは、コマンドパレットの「テストプレイ(外のブラウザで)」を使います。
- **反映した内容を試す**: ゲームに反映したあと、ゲームのタブを読み直すと効きます。
- **止める**: 「操作」→「試す・デバッグ」→「テストプレイを止める」。

テストプレイのセーブは、VS Code の中に残ります。次のテストプレイでも続きから遊べます。
ツクールでのテストプレイのセーブとは別になります。

### デバッグメニュー

「操作」→「試す・デバッグ」→「デバッグメニューを表示」で、エディタのタブに開きます。
画面の下のパネル「Text2Frame デバッグプレイ」にも、同じものが出ます。

| 欄 | 見られるもの | できること |
| --- | --- | --- |
| スイッチ | すべてのスイッチの ON / OFF | 押して切り替える |
| 変数 | すべての変数の値 | 値を打って Enter で書き換える（文字は `"…"` で囲む） |
| イベント | 今いるマップのイベント。今出ているページ（`P2` など）、並列処理で動いているもの（「並列」の印）、セルフスイッチ A〜D | セルフスイッチを押して切り替える。イベント名を押すと、そのテキストとプレビューが開く |
| アイテム | 所持金と、持っているアイテム・武器・防具の数 | 数を打って Enter で書き換える。「すべて」で、持っていないものも並ぶ |

- イベントの左の ▸ を押すと、ページごとの**出現条件**（スイッチ・変数・セルフスイッチ・アイテム・アクター）と**トリガー**（決定ボタン・自動実行・並列処理など）が出ます。
  - 条件ごとに、今の値で満たしているかが ✓ / ✗ で分かります。
  - ツクールは、条件がそろったページのうち番号がいちばん大きいものを動かすので、「なぜ今このページなのか」が分かります。
- 上の欄で、番号や名前で絞り込めます。「OFF・0 を隠す」にチェックを入れると、ON のスイッチや 0 でない値だけになります。
- スイッチで動く並列処理のコモンイベントは、イベントの欄のいちばん上に出ます。
- 変わったばかりの値は、少しの間光ります。

### このイベントから試す

テキストのいちばん上に、小さなリンクが出ます。押すと、テストプレイでそのイベントをすぐ試せます。最初から歩いていく必要はありません。
「操作」→「試す・デバッグ」の**▶ イベントの前に立つ**・**▶ このページをすぐ実行**でも、同じことができます（今開いているテキストが相手です）。

| リンク | 何をするか |
| --- | --- |
| ▶ イベントの前に立つ | そのマップへ移動して、イベントの隣に、イベントの方を向いて立ちます。話しかける・触れるのは自分で行うので、出現条件やトリガーもゲームのとおりに試せます |
| ▶ このページをすぐ実行 | そのマップへ移動して、このページの中身をすぐ動かします（出現条件は見ません） |
| ▶ すぐ実行（コモンイベント） | 今いる所で、そのコモンイベントを動かします |

- テストプレイが動いていなければ始め、タイトル画面なら新しいゲームを始めます。
- 実行中のイベントやメッセージは止めてから移動します。
- プレイヤーが透明（「透明状態で開始」や、演出の途中で止めたとき）でも、見えるようにしてから立たせます。「このページをすぐ実行」で、透明かどうかをゲームのそのときのままにしたいときは、設定 `text2frame.tryEvent.clearPlayerTransparency` をオフにします。
- テキストにゲームへ反映されていない変更があれば、「反映して試す」か「このまま試す」かを聞きます。「反映して試す」を選ぶと、反映してゲームを読み直してから試します。
- **「Maps / Common Events」一覧の行を右クリック**しても、同じことができます。まだテキストの無いページでも試せます。
- 「操作」から押すときは、先に試したいテキストを開いてください。開いていないと、その旨を知らせます。

### 今実行している行を見る

テストプレイ中にイベントが動くと、そのテキストの**実行中の行に色が付きます**。
画面の左下にも「実行中のイベント名と行」が出て、押すとその行が開きます。

- デバッグメニューの「実行中のテキストを開く」にチェックを入れると、実行中のイベントのテキストが自動で開きます。ゲームの操作はそのまま続けられます。
- テキストがゲームのデータと少し違うときは、いちばん近い行に「(近い行)」と出ます。反映してゲームを読み直すと合います。
- 並列処理のイベントは、行の色付けの対象外です（デバッグメニューの「並列」の印で分かります）。

### 印をつけた行で一時停止して調べる

「この行まで来たら、ゲームを止めたい」ときに使います。止まったところで、スイッチや変数の値を見たり、1行ずつ進めたりできます。

1. テキストの行番号の左をクリックすると、赤い丸の**一時停止の印**が付きます（プログラムでいうブレークポイントです）。もう一度クリックすると消えます。
2. 「操作」→「上級」→「**印をつけた行で一時停止する**」を押して、**オン**にします。もう一度押すとオフに戻ります（名前の横に今の状態が出ます）。ゲームのフォルダごとに覚えています。
3. テストプレイ・「▶ このページをすぐ実行」・「▶ イベントの前に立つ」のどれで始めても、その行まで来るとゲームが止まります。テキストのその行が黄色くなります。

止まると、次の2つが出ます。

- ゲームの画面の上に「一時停止中」の帯
- VS Code の右下に「一時停止しました: （ファイル名）の（行）行目」の知らせ。「**続ける**」で先へ進み、「**印をすべて消して続ける**」で印を全部消してから進みます

オフのとき（最初はオフです）は、印があってもゲームは止まりません。オフのまま印を付けると、オンにするかを一度だけ聞きます。
すぐにその場で始めたいときは `F5` でも始まります（テストプレイが動いていなければ始めます）。

止まっている間は、左の「実行とデバッグ」の欄で調べられます。

| 欄 | 見られるもの |
| --- | --- |
| 変数 | スイッチ・変数・このイベントのセルフスイッチ・所持金とアイテム。値をダブルクリックすると書き換えられます |
| ウォッチ | 見たい番号を足しておけます。`S12`（スイッチ12）、`V5`（変数5）のように書きます。`スイッチ12`・`変数5` でも書けます |
| コール スタック | 今どこを動いているか。コモンイベントの中なら、呼び出したイベントも下に並びます。押すとその行が開きます |

画面の上に出る小さなボタンで、続きを動かします。

| ボタン | 何をするか |
| --- | --- |
| ▶ 続行（`F5`） | 次の印まで動かします |
| ⤼ ステップ オーバー（`F10`） | 1行進めます。コモンイベントの呼び出しは、中に入らずに終わりまで動かします |
| ⤓ ステップ イン（`F11`） | 1行進めます。コモンイベントの呼び出しなら、その中に入ります |
| ⤒ ステップ アウト（`Shift+F11`） | 今のコモンイベントの終わりまで動かして、呼び出した側で止まります |
| ⏸ 一時停止 | 次に動くコマンドのところで止めます |
| ■ 停止 | テストプレイごと止めます（「テストプレイを止める」と同じ） |

- 空行や注釈に付けた印は、その次のコマンドで止まります。
- 印が灰色になっているときは、そこでは止まりません。丸にマウスを乗せると理由が出ます。多くは「ゲームに反映されていない」ので、反映してゲームを読み直すと効きます。
- 並列処理のイベントでも止まります。
- 「このイベントから試す」で移動している間は止まりません。止まっている間に押すと、ゲームを動かしてから移動します。

## 英語版（多言語版）を作る

この拡張に翻訳の機能はありません。言語ごとにテキストのフォルダを分けて、切り替えて使います。

1. 設定 `text2frame.textBaseDir` を `text-en` に変え、「ゲームから取り出す」→「すべて」を押します。
   `text-en` に、翻訳の出発点になるテキストがそろいます。あとで何度取り出しても、訳した文は消えません。
2. `text-en` のセリフと選択肢を訳します（先頭の `---` の部分、タグ、`<br>` は触らない）。
3. 「ゲームに反映」→「すべて」を押します。ツクール側で加えた編集は残ったまま、訳文が入ります。

日本語版に戻すときは、`text2frame.textBaseDir` を `text` に戻します。
白紙からやり直したいときだけ、「上級」→「全部取り直す(上書き)」を使います（訳文は消えます）。

## 設定

VS Code の設定画面（`Ctrl+,` / `Cmd+,`）で `text2frame` と検索すると出てきます。
**ふだんは全部そのままで大丈夫です。**

| 設定 | 既定 | 何を決めるか |
| --- | --- | --- |
| `text2frame.strategy` | 安全に統合 | ゲームへの入れ方。「安全に統合」はツクール側の編集を消しません。「テキストで全部上書き」も選べます |
| `text2frame.reviewBeforeApply` | ON | ボタンで反映・取り出すとき、変わる所を差分で見せてから書き込むか |
| `text2frame.writeBackAfterMerge` | 反映のたび | 統合で反映したあと、ゲーム側の変更もテキストに書き戻すか（反映のたび / 書き戻さない）。競合したときは、どちらでもテキストに書き戻します |
| `text2frame.englishTag` | ON | 取り出すときのタグを英語（`<Face: >`）にするか、日本語（`<顔: >`）にするか |
| `text2frame.omitDefaultTags` | ON | 取り出すとき、既定のままの顔・背景・位置のタグを省くか |
| `text2frame.showDatabaseNames` | ON | 番号の横に、データベースの名前を薄く出すか |
| `text2frame.messageCheck` | 自動 | メッセージのはみ出しを調べるか（自動 / いつも / 調べない）。自動は、自動で改行するプラグインが有効なら調べません |
| `text2frame.history.keep` | 100 | 反映・取り出しの前の中身を、何回ぶん控えておくか（[前の状態に戻す](#前の状態に戻す履歴)）。0 にすると控えません |
| `text2frame.tryEvent.clearPlayerTransparency` | ON | 「このページをすぐ実行」で試すとき、プレイヤーの透明化を解除してから始めるか（[このイベントから試す](#このイベントから試す)） |
| `text2frame.messageLineLength` | 0 | 顔の無いメッセージの1行に入る文字数（全角）。0 なら自動で決めます |
| `text2frame.usageContextLines` | 2 | 「使っている箇所」の一覧に、前後を何行ずつ出すか |
| `text2frame.openRunningText` | OFF | テストプレイ中、実行しているイベントのテキストを自動で開くか |
| `text2frame.testPlayPage` | （空） | テストプレイで開くページ。空なら自動で選びます |
| `text2frame.textBaseDir` | `text` | テキストを置くフォルダ |
| `text2frame.dataDir` | `data` | ゲームのデータのフォルダ |
| `text2frame.modulePath` | （空） | 変換プログラム `Text2Frame.js` の場所。ふつうは空のままで、自動で見つかります |

## 困ったとき

| こんなとき | どうする |
| --- | --- |
| 反映したのに、ツクールで見ると変わっていない | ツクールのエディタを**保存せずに**開き直してください。開いたまま保存すると、古い内容で上書きされます |
| 反映を押しても書き込まれない | 差分の画面が開いているはずです。右上の「✓」か、通知の「反映する」を押すと書き込みます |
| 画面の左下が `T2F fail` になる | 書き方の間違いです。`T2F fail` を押すと理由が出ます。`< >` の閉じ忘れがよくあります |
| テキストに目印の3行が入っている | 両方で同じ場所を変えた印です。残したい方だけにして3行を消し、もう一度反映してください |
| 取り出したら、書いた文が消えた | 「全部取り直す(上書き)」を使うと消えます。ふだんは「ゲームから取り出す」を使ってください |
| `.txt` に色が付かない | 先頭に `---` で囲まれた宛先のメモがあるファイルだけが対象です |
| 「ツクールのプロジェクトが見つかりません」と出る | ゲームのフォルダ（`data` があるフォルダ）を開き、そのテキストを開いてからもう一度試してください |
| テストプレイの画面が真っ黒・エラーになる | 設定 `text2frame.testPlayPage` に、ゲームのフォルダで最初に開くページ（例: `index.html`）を入れてみてください |
| デバッグメニューに何も出ない | テストプレイでゲームが始まると出ます。タイトル画面の間は、まだ値がありません |
| 番号の横に名前が出ない | ゲームのフォルダを開いているか確かめてください。「データベース」一覧の「データベースを読み直す」でも直ることがあります |

## 動かすのに必要なもの

**VS Code 1.85.0 以上だけです。** Node.js などを別に入れる必要はありません。Windows でも Mac でも動きます。

<details>
<summary>技術的な補足（変換プログラムの探し方）</summary>

変換を行う `Text2Frame.js` は、次の順に探します。

1. 設定 `text2frame.modulePath`（指定がある場合）
2. 拡張に同梱した `lib/Text2Frame.js`
3. 1つ上のフォルダの `Text2Frame.js`（開発時）
4. 開いているフォルダの中の `Text2Frame.js`（`js/plugins/Text2Frame.js` も探します）

</details>

<details>
<summary>開発者向け</summary>

```bash
npm install        # 依存をインストール
npm run compile    # TypeScript をビルド（out/）
npm run watch      # 変更を監視してビルド
npm run lint       # ESLint
npm test           # テスト
```

`F5` で Extension Development Host を起動するとデバッグできます。
パッケージ（`.vsix`）にする前に、`npm run bundle-compiler` で親リポジトリの `Text2Frame.js` を `lib/` にコピーします（`vscode:prepublish` で自動で実行されます）。
ターミナルから同じことをしたい場合は、本体リポジトリの CLI（`npx t2f-sync --watch` など）もあります。

</details>
